# T9.6 出口服务器交付结果

## 实现

- 服务器详情的「出口」标签可选择另一台已管理服务器，可编辑 AI、流媒体、精确域名和后缀规则，并可切换分流或全部代理流量。默认分流，发生故障时默认阻断，可主动开启直连回退。客户端继续使用现有入口。
- 入口按用户保持原有流量计数方式。出口的「流量」标签新增单独的累计转发量，使用 Linux 内核计数，包含探测流量。
- 入口每 30 秒经出口做 HTTPS 探测。连续两次失败后应用故障策略，一次成功后恢复。出口状态显示探测与策略生效进度，告警复用面板事件和通知队列。
- 每条链路有自己的专用入站、自动分配端口和服务凭证。出口的 TCP/UDP 防火墙守卫只允许该入口公网 IP。生效、回滚和独立重启均恢复相应守卫。更换、停用或移除时清理两端，远端重连后收敛。
- 升至节点协议 3 以识别出口能力。协议 2 继续进行原有同步，面板显示「需升级节点」。T9.4 快照继续保留出口关系、密钥和端口，迁移后相关节点接收新主控的链路公网 IP。

## 协议和规格

选择 Shadowsocks-2022 的 `2022-blake3-aes-256-gcm`。每条链路使用 `crypto/rand` 生成独立 32 字节密钥，支持 TCP 和 UDP，也省去了 Reality 的握手站点、域名和证书配置。链路密钥通过签名认证的节点接口下发给对应两端。用户入站、订阅和管理预览经过隔离或脱敏。

服务器出口规则单独存储。两端继续执行 BT 和私有地址保护，内部入站在出口直接出网。入口和出口使用同一地址族的公网 IP。若已有域名无法提供链路地址，可在「出口」标签填写公网 IP。外部手填代理留作后续，L4 端口转发另列为 T9.7。

规格见 [T9.6](TASKS.md#t96-出口服务器) 和 [服务端出口配置](CONFIG.md#8-t96-服务端出口)。
