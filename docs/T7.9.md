# T7.9 实现与评审记录

对应 [TASKS.md](TASKS.md#t79-通知与告警) 的 T7.9「通知与告警」。新增 SQLite 迁移 `0003_alerts.sql`，沿用项目现有依赖和生效流程。

## 请求格式与官方依据

- Bark 通过 HTTPS `POST /push` 发送 JSON `device_key`、`title`、`body`。自建地址可带反代路径。
  校验 HTTP 状态及响应 `code=200)。[Bark API V2](https://github.com/Finb/bark-server/blob/master/docs/API_V2.md) · [Bark 推送路由](https://github.com/Finb/bark-server/blob/master/route_push.go)
- Server 酱 Turbo 使用 `POST https://sctapi.ftqq.com/{SendKey}.send`，表单字段 `title` 和 `desp`，成功为 `code=0`。
  [Server 酱 Turbo SendKey 文档](https://sct.ftqq.com/docs/getting-started/sendkey/#验证-sendkey-是否可用)
- Telegram Bot 通过 `POST https://api.telegram.org/bot{token}/sendMessage` 发送 JSON `chat_id` 和 `text`，检查 `ok=true`。
  [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage)

## 规格补齐

- 额度采用十进制整数 GB。网卡选择优先 IPv4 默认路由，最低 metric 优先，IPv6 为后备。结束采样时刻所属的 UTC 周期接收整段增量。
  保留最近 62 天样本，切换网卡以新计数建基线并保留本期已记用量。具体误差边界见 [SPEC §16](SPEC.md#16-t79-服务器流量通知与告警)。
- 用户配额去重以流量 epoch 为周期，到期事件按所设到期秒去重。用稳定的用户身份处理 SQLite ID 复用。
  自动停用和实际 Apply 在同一事务提交。服务器用量按计费周期起点去重，证书按所用证书到期时刻，内核按持续停机事件去重。
- 测试发送复用持久化队列，返回队列 ID 后可在概览看结果。滚动小时预算涵盖重试和测试，溢出合并为摘要。
  概览保留每项事件。在服务商接收后、本地确认前崩溃时，续投可能产生重复外部通知。
- 通道响应和日志仅使用固定错误摘要。自建 Bark 保存在通过公网 DNS 校验后，HTTPS 建连时重新验证并固定已验证的目标 IP，
  保留原始域名进行 TLS 校验。禁止重定向和代理。
