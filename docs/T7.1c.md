## 问题与最终行为

Clash API 只能返回仍存活的连接，真机 20,000,000 字节下载只记到约 26%。现已删除
`/connections` 采集、连接 ID/start/chains 基线及 HTTP 凭证传递，改为 Linux 内核累计计数，
短连接关闭后仍可读取其累计字节。Clash 控制器的既有配置/诊断能力保持。

- Linux 生产的 `direct-u<ID>` 增加整数 `routing_mark=0xb7000000+ID`。
  ID 仅接受 1–16777215，超范围拒绝生成并提示修复，不截断；原 direct、服务器 DNS、Reality 握手不加 mark。
  保留 auth_user 及 sniff/BT reject/resolve/private reject 的顺序，客户端订阅无变化。
- 独立 `inet boxpanel_traffic`：output/input 都是 filter 基链，priority mangle（-150），
  在 conntrack（-200）之后处理每个 TCP/UDP 包。output 保存 meta mark 到 ct mark 并累计上传；
  input 匹配 ct mark + reply 方向累计下载。支持 IPv4/IPv6、TCP 与 UDP/QUIC，避免回环原方向被计成下载。
- 命名计数器 `up_u<ID>` / `down_u<ID>`；同步只 flush 两条链的规则引用、保留交集 counter 对象，
  增加新用户计数器、删除离开用户的计数器。nft 单批事务原子下发，不改其他表或规则集。
  统计基链不作为管理员 INPUT 防火墙参与检测/端口放行。
- `traffic_users` 加入原 applied_firewall、pending 前后计划、恢复 union 和卸载清理。
  旧 JSON 缺字段视为空，不需迁移；失败仍回滚 DB/文件/服务和前计划，恢复失败保留 journal。
  规则恢复不重置仍存在的命名计数器；已删计数器若需恢复则从零重建。
  T7.1b 配置/计划相同且运行中的 metadata/token/清零操作仍只提交 DB，不触碰 nft。
- 每 10 秒读取 `nft -j list counters table inet boxpanel_traffic`。首次成功只建基线，
  后续按用户/方向计差值，减小视为重建并从当前值累计。用户删除回收基线，未知用户忽略。
  失败保留基线/增量；不完整计数对、重复、负数、损坏响应拒绝推进，uint64 饱和至 int64。
  保留 60 秒短事务落库、epoch 重置隔离、批次核对/重试、30 秒合并停用/月度调度。
- 安装在缺 nft 时始终安装 nftables，即使已有完整 iptables；旧实例 update 也会先补齐此依赖。
  apt/dnf 同名包，仍沿用有界锁等待，不启用防火墙服务。无 nft 近似统计退路，失败明确给下一步。
- 面板、分享页、SPEC/API/CONFIG/INSTALL/FRONTEND 同步说明：计数为服务器与目标站点之间的
  IP 层字节，含协议头/ACK/重传，不含客户端加密开销、服务器自身 DNS；与客户端可有差异。

## 官方依据与最小规格补齐

1. [sing-box v1.14.4 Dial Fields / routing_mark](https://github.com/SagerNet/sing-box/blob/v1.14.4/docs/configuration/shared/dial.md#routing_mark)
   明确支持整数/十六进制字符串且仅 Linux，采用整数；
   [在线官方文档](https://sing-box.sagernet.org/configuration/shared/dial/#routing_mark) 同义。
2. [nftables 官方 nft(8)](https://www.netfilter.org/projects/nftables/manpage.html)：
   CHAIN 中的 hook/priority 表、COUNTER 的命名对象与 `counter name`、CONNTRACK STATEMENT 的
   `ct mark set meta mark`、CONNTRACK EXPRESSIONS 的 direction/mark、以及 `-j` JSON 输出及 list 命令。
   用 filter 而非 NAT 链以覆盖所有包；mangle 在 conntrack 之后才可读取/保存连接标记。


规格原先未指定的 mark 范围、计数器名、链优先级/回环方向、升级依赖、统计口径与平台验证方式已补齐。
macOS 锁定内核在 `check` 时就拒绝 Linux routing_mark：golden 测试实际断言此限制，
再仅从临时校验副本去掉 marks 并 check 其余字段；Apply 的真实 check 测试同样用临时宿主副本。
Linux 直接 check 原始带 mark 配置。生产 staged 文件、校验入口与激活路径始终不改写/绕过。

不承诺精确计费：历史计数不补算；面板停机到重启首次基线间不补算；系统/表重建或删除用户计数器时
未采样尾段会丢失；强退可能丢失尚未落库增量。手动/月度清零后首次采样重新建立 epoch 基线，
不把重置前字节写回。这些边界见 SPEC §14，正常保留的内核计数器已消除短连接轮询漏计。
