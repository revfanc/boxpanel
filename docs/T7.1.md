## 行为与调研结论

原实现从不写 traffic_up/down，到期也仅在无关 Apply 时移出用户。
现在 Linux 生产 serve 共用一个后台循环：5 秒采集、60 秒落库、30 秒检查有效期/配额/月度清零。
需要变更时合并到一次原 Manager.Apply，成功后断开旧连接、移除失效用户，失败保留原回滚与恢复记录。
提高限额、延期、重置用量均使用原资源生效流程恢复。

锁定 **sing-box v1.14.4** 的源码证据：

1. [experimental/clashapi/connections.go L80–99](https://github.com/SagerNet/sing-box/blob/v1.14.4/experimental/clashapi/connections.go#L80-L99)
   的 metadata 没有入站认证用户名；processPath 的系统用户信息不代表认证用户。
   同处输出累计 upload/download、start 和 chains。
2. [common/trafficcontrol/tracker.go L62–77](https://github.com/SagerNet/sing-box/blob/v1.14.4/common/trafficcontrol/tracker.go#L62-L77)
   将出站链 tag 放入 Chain，并生成连接 UUID、CreatedAt。
3. [connections.go L29–43](https://github.com/SagerNet/sing-box/blob/v1.14.4/experimental/clashapi/connections.go#L29-L43)
   使用 [Manager.Connections L129–136](https://github.com/SagerNet/sing-box/blob/v1.14.4/common/trafficcontrol/manager.go#L129-L136)
   的当前存活连接，不能从该接口取得已关闭连接的最后计数。
4. [锁定版本 auth_user 文档 L218–220](https://github.com/SagerNet/sing-box/blob/v1.14.4/docs/configuration/route/rule.md#L218-L220)
   确认可按入站认证用户名匹配路由。

因此按任务备用方案生成每用户 `direct-u<ID>` 普通 direct 出站，在原安全规则之后添加 auth_user 路由；
从 chains 归属用户。保留 sniff、BT 屏蔽、resolve、私网拒绝及顺序，不引入 v2ray_api 或自编译内核。
配置生成 golden 和显式路由顺序测试同步，锁定 1.14.4 check 通过。

## 最小补齐与一致性

- `0002_user_traffic.sql` 追加 traffic_reset_day、traffic_reset_at、内部 traffic_epoch。
  原迁移不修改，旧用户默认关闭月度清零，已有计数保留；升级、幂等、约束和事务回滚有测试。
- reset-traffic 为认证 + CSRF + 空 body 的 POST，按完整 Apply 清零并返回脱敏用户。
  清零、reset_at、epoch 同事务；旧 epoch 的内存增量不会重新写回。新用户用 crypto/rand 初始化 epoch，
  防止 SQLite 复用删除用户 ID 时继承旧待写增量；内部 epoch 不出 API。
- 月度只处理 UTC 本月已到的日期边界，reset_at 防重复；离线跨月只补当前月已到边界。
  当月边界后的手动清零抑制当月再次自动清零；0 关闭，不改变 enabled 或 expire_at。
- 采集在读事务完成后请求回环 API，禁止代理/重定向、响应有界；只有批量 SQL 在短写事务中执行，
  Flush context 至多 1 秒，写池仍保持既有 busy timeout。读 API 继续使用独立 WAL 池。
- settings.applied_users 与配置 generation 同事务记录实际用户，避免每轮重复重启；
  调度先用已提交数据和待写增量判断，再在 Apply 写事务中重新核对，变化过时则不重启。
- settings.traffic_batch 与增量同事务写入；提交结果不确定时先核对批次再重试，避免重复累计。
  Apply 失败时保留增量；后台生效失败 30 秒起指数退避，上限 10 分钟，采样/定期落库继续。
- 面板列表/详情、分享页和 Subscription-Userinfo 使用真实已落库计数；表单及详情显示 UTC 月度计划，
  详情支持清零确认/失败重试。所有文案在 zh-CN.ts，保存提示全连接约 1 秒中断。
- **近似误差**：轮询间新建并关闭的短连接及关闭尾段会漏计，重启/采样故障也会遗漏；
  崩溃可能丢失尚未保存的增量。通常 60 秒保存一次，失败时延迟更长，不用于精确计费。
  正常退出最后采样并尽力落库，失败有修复提示。SPEC §14、API、CONFIG、FRONTEND 已同步。
